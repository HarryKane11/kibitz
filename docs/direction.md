# 작업 방향

이 문서는 **다음 작업자(사람 또는 에이전트)를 위한 인계 문서**다. 무엇을 만들지보다
**무엇을 깨면 안 되는지**가 먼저 나온다 — 이 저장소에는 의도적으로 하지 않기로 한
것들이 있고, 그것을 모르고 고치면 제품의 근거가 사라진다.

읽는 순서: §2 원칙 → §3 UX 규율 → §5 작업 항목. §1과 §4는 참조용.

## 2. 깨면 안 되는 원칙

1. **LLM은 판정하지 않는다.** 모델에게 "이 런 괜찮았어?"를 묻지 않는다. 모델의 유일한
   일은 *계산된 판정을 놓고 무엇을 바꿀지 제안*하는 것이고, 그 제안의 인용은
   `suggest.ts`의 `CITATION_RULE`로 검증한다. 새 화면에 AI 텍스트를 추가할 때도
   **검증을 함께 추가**한다.
2. **탐지 규칙 구현은 하나뿐이다** (`agent/kibitz_ingest`). TypeScript로 옮기지 않는다.
   두 구현은 반드시 갈라지고, 갈라지는 순간 두 트레이스를 나란히 볼 이유가 없어진다.
3. **모든 판정에는 관측값이 붙는다.** 근거 없는 판정은 머지하지 않는다.
4. **실제 세션 데이터는 커밋하지 않는다.** `web/lib/mock/traces.json`과
   `web/lib/mock/*.local.json`은 gitignore. 데모는 `traces.demo.json`(합성, 영어).
5. **공개 배포에서는** 익명 수집과 붙여넣은 API 키를 받지 않고 로컬 CLI 에이전트를
   쓰지 않는다 (`lib/deploy.ts`). 이 가드를 우회하지 말 것.
6. **데이터에 사람 말을 넣지 않는다.** 국면·판정·근거는 키로 저장하고 문자열은
   `lib/i18n/dictionaries.ts`에서 온다 (`en`이 타입 원천). 단, **에이전트 자신의 말**
   (턴 제목·출력·사용자 발화)은 번역하지 않는다.
7. **색은 셋뿐이다.** `sky`(선택) · `warn`(낭비) · `crit`(오류). 정상과 사람 개입은
   색을 쓰지 않는다.

## 3. UX 규율 (이번에 새로 정함)

현재 판정 문구 5개 중 4개가 **무슨 일이 일어났는지**만 말한다. 사용자는 **그래서 뭘
손해봤는지**를 알아야 한다. `cache-break`의 `"Paid for the same context twice"`가
유일하게 옳은 형태이고, **이것이 템플릿**이다.

1. **첫 줄은 손해, 단위는 시간과 돈.** 토큰은 내부 단위다. 사람은 "12분을 기다렸는데
   불필요했다"를 이해한다.
2. **메커니즘은 접는다.** 해시·턴번호·규칙식은 "왜 이렇게 판단했나 ▸" 뒤에 둔다.
   **없애지 않는다** — 증거가 이 제품의 유일한 해자다. 순서만 바꾼다.
3. **집계 창을 넓힌다.** 런 1건의 $0.25는 아무도 신경 쓰지 않는다. 기간 단위로 모아라.
4. **비교 기준을 준다.** "7.3%"는 그 자체로 의미가 없다. 중앙값과 함께 보여야 읽힌다.
5. **모든 판정은 행동 하나로 끝난다.** `agent-rules.ts`가 이미 그 형태다.

읽기 레벨은 둘이다. 기본은 결과(코드 에이전트 사용자), 파고들면 메커니즘(SDK 사용자).
쉽게 만드는 것이 아니라 **기본값을 바꾸는 것**이다.

## 4. 방향

**개인용 도구로 간다.** 팀/인프라 경로(Langfuse 31.9k, Phoenix 10.7k)는 3년 앞서 있고
정면 경쟁은 진다. 코드 에이전트 세션 분석은 1등이 3.6k(`claude-devtools`)라 아직 비어
있다.

- **"Langfuse 대체재" 프레임을 앞세우지 않는다.** 지운 화면이 많아 기능 비교로 가면 진다.
- 경쟁자 대비 한 줄: claude-devtools는 *무슨 일이 있었는지*, Usage Monitor는 *얼마 썼는지*
  보여준다. **kibitz는 무엇이 낭비였는지 보여주고 그것을 증명한다.**
- 제품의 최종 형태는 뷰어가 아니라 **컨트롤 루프**다: 관측 → 판정 → 개입 → **재측정**.
  마지막 단계(적용한 규칙이 효과가 있었는지 다시 재는 것)를 할 수 있는 곳은 여기뿐이다.

**MCP는 관측 수단이 아니다.** MCP 서버는 호스트가 다른 툴로 무엇을 했는지 볼 수 없다.
캡처는 JSONL 워처, 실시간 개입은 훅, 질의는 MCP다. 셋을 하나로 묶는 포장은
**Claude Code 플러그인**이다(스킬·훅·MCP를 함께 담는다).

## 5. 작업 항목

### P0 — 지금

**5.1 판정 문구 전면 재작성**
`lib/i18n/dictionaries.ts`의 `note` 블록과 `evidence` 라벨. §3 규율 적용. en/ko 양쪽.
완료 조건: 모든 판정이 "무엇을 손해봤는가"로 시작하고, 해시·턴번호는 접힌 블록에만 있다.

**5.2 `npx kibitz`**
현재 첫 화면까지 4단계(pnpm install → dev → uv sync → cli). 경쟁자는 한 줄이다.
**이것이 모든 홍보의 전제다.** 한 명령으로 인제스트 + 브라우저 오픈.

**5.3 저장소 위생**
`.github/`(CI·이슈/PR 템플릿) 없음, `CONTRIBUTING.md` 없음, og:image가 GitHub 기본값
(링크 공유 시 밋밋한 카드). 브랜드 에셋은 `web/public/brand/`에 이미 있다. 반나절.

### P1 — 컨트롤 루프

**5.4 미사용 툴 정리 UI** ← 가장 작고 가장 남다름
`unusedToolTokens`는 이미 계산되어 화면에 떠 있다. 행동 버튼만 없다.
> 툴 41개 등록, 9개 호출. 나머지 32개 정의가 매 호출 2,890토큰 · 41세션 동안 0회 사용

마켓플레이스는 "추가하세요"만 말한다. **"이건 빼세요"를 근거와 함께 말할 수 있는 곳은
여기뿐이다.**

**5.5 `kibitzd` — 로컬 데몬**
`--watch` 재사용. 워처(JSONL tail) + 감사 큐. 트리거는 **시계가 아니라 변경**이다:
판정 집합 해시가 같으면 모델을 부르지 않고 캐시를 돌려준다. 사용자는 주기를 정하고
수동 refresh도 할 수 있지만, 실제 실행은 변경이 있을 때만.

**5.6 탭별 브리프**
`lib/analysis/brief.ts`가 런 1건 전제다. Usage/Failures/Skills/Sessions 각각의 입력으로
일반화. **모든 탭에 인용 검증을 함께 적용**한다(§2-1).

**5.7 규칙 효과 측정 = 루프를 닫는 지점**
`agent-rules.ts`에 "적용함" 표시를 두고, 이후 세션에서 해당 판정률을 추적한다.
> 7월 20일 규칙 추가 → 이후 18세션에서 중복 호출 7.3% → 2.1%

이걸 할 수 있는 건 트레이스를 가진 쪽뿐이다.

### P2 — 밖으로 나가는 것

현재 kibitz는 화면이 좋은데 **밖으로 나가는 산출물이 없다.** 90k·13k짜리 레포들은
전부 앱이 아니라 산출물이다.

**5.8 PR 봇** — 분포 관점 최강
기존 리뷰 봇은 전부 **diff**를 읽는다. kibitz는 **과정**을 읽는다. 그래서 남들이
원리적으로 못 하는 체크가 있고, 전부 LLM 없이 된다:

- 읽지 않고 고친 파일 (트레이스의 Read 대상 ∖ diff 변경 파일 — 순수 집합 연산)
- **PR 설명의 출처 없는 숫자** (`unsourced-number`를 PR 본문에 적용) ← 데모 최강
- 컨텍스트를 벗어난 지시 ↔ diff 교차 검증
- 리뷰 난이도 라우팅 ("400줄인데 11턴, 테스트 0회" vs "12줄인데 89턴, 루프 6회")

v1은 인프라 0으로 가능하다: `kibitz pr`이 로컬에서 최근 트레이스 + 브랜치 diff를
대조해 `gh`로 코멘트. 커밋 트레일러 `Kibitz-Trace: <id>`로 연결.
**포지션은 대체재가 아니라 보완재다** — 다른 봇은 코드를, kibitz는 그 코드를 만든
과정을 본다. PR당 코멘트는 **하나만**.

**5.9 `kibitz report` / score + 배지**
개인 숫자가 공유를 만든다. 0–100 점수와 README 배지는 Lighthouse·codecov 패턴이다.

**5.10 마켓플레이스 제안 — 존재 검증이 핵심**
`skills.ts`가 채굴한 반복 시그니처가 곧 검색 쿼리다. 결정론이 쿼리를 만들고,
레지스트리를 조회하고, LLM은 매칭과 문장만 쓴다. 그리고 **`cited server ∈ registry
results`로 검증**한다 — `CITATION_RULE`을 새 도메인에 그대로 적용.
없는 패키지명을 추천하면 그건 공급망 공격면이다.
- 공식 MCP Registry: `registry.modelcontextprotocol.io/v0/servers?search=` — **인증 불필요**, 기본값
- Smithery: `api.smithery.ai/servers?q=` — API 키 필요, `useCount`·`verified` 랭킹 보강용

## 6. 함정

1. **MCP ≠ 관측.** MCP 설치만으로는 트레이싱이 켜지지 않는다. 캡처는 워처다.
2. **감사의 자기 재귀.** 감사를 돌리면 그 감사 자체가 Claude Code 세션이고, 워처가
   그것을 수집하고, 다음 감사가 그것을 분석한다. **감사 세션에 마커를 심고 인제스터가
   걸러야 한다.** 안 하면 무한 루프 + 쿼터 폭발.
3. **쿼터와 동시성.** 감사는 사용자의 구독 쿼터를 쓴다. 하루 상한, 사용량 표시,
   그리고 사용자가 활동 중이면 미루는 정책이 필요하다. 낭비를 잡는 도구가 스스로
   낭비하면 그날로 삭제된다.
4. **PR 코멘트 리댁션.** 공개 PR에 프롬프트·파일 내용이 나가면 끝이다. 파생 숫자와
   **이미 diff에 있는 경로만** 화이트리스트로 내보낸다.
5. **서버리스 파일시스템.** `/tmp` 외에는 읽기 전용이다. 쓰기는 예외를 던진다.
   `docs/deployment.md` 참조.
6. **`.git.disabled-nested-repo/`.** 작업 트리에 중첩 git 디렉터리가 생길 수 있다.
   커밋에 포함시키지 말 것.

## 7. 열린 질문

- **hermes · openclaw 어댑터** — 세션 로그 포맷과 경로를 모른다. 샘플 파일이 필요하다.
  구조는 작다: `agent/kibitz_ingest/adapters/*.py` → 이벤트 → `build.py`.
- **훅 지원 범위** — Claude Code에는 있다. Codex 등에도 있는지 확인 필요. 없으면 그쪽은
  워처 기반 준실시간(관측만, 개입 없음)으로 시작한다.
- **문서 언어** — `docs/` 13개 전부, 소스 52개 중 49개가 한국어 주석이다. 기여자는
  1k→10k를 만드는 엔진인데 지금 구조는 스타는 받아도 기여는 못 받는다. 기본값을
  뒤집을 시점을 정해야 한다(영어 기본 + `README.ko.md`·`docs/ko/`). 이 문서도 그때 함께
  옮긴다.
