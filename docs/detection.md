# 탐지 규칙

현재 인제스터가 판정을 만드는 여섯 규칙은 **LLM 없이** 계산됩니다. 판정마다 그것을
계산해낸 값이 함께 붙습니다.

| 규칙 | 계산 |
|---|---|
| `repeated-call` | `hash(도구, 인자)` 가 앞선 호출과 같음 **且** 그 사이 대상에 쓰기 없음 |
| `call-cycle` | 호출 시퀀스에 길이 2+ 반복 부분열 |
| `empty-result-loop` | 결과 0건 뒤 인자 변경 없이 같은 도구 |
| `context-eviction` | 직전 호출의 message id가 다음 실제 message 목록에서 사라짐 |
| `cache-break` | 캐시 읽기 급락 + 캐시 쓰기 급증 |
| `unsourced-number` | 출력의 숫자 리터럴 ∉ (도구 출력 ∪ 사용자 입력) |

`context-eviction`은 runtime이 실제 model call에 전달한 `message_ids`를 제공할 때만
계산합니다. ID가 없는 adapter에서 추정하지 않으며, cache 급락은 별도의 `cache-break`로
판정합니다. Python SDK에서는 `span.set_context([...])`로 전달할 수 있습니다.

## 왜 LLM 을 안 쓰는가

모델에게 "이번 런 괜찮았어?"를 물으면 그 대답 자체가 또 하나의 검증 못 하는 것이
됩니다. 사람은 그걸 확인할 방법이 없고, 결국 "모델이 그렇다니까"가 됩니다.

그래서 범위가 좁습니다. `unsourced-number` 는 의미를 보지 않고 숫자 리터럴만
문자열로 대조합니다. 단위 변환·표현 변화에서 놓치거나 같은 숫자가 우연히 존재할 수
있으므로 의미 검증으로 해석하면 안 됩니다. 장점은 판정 근거를 그대로 띄울 수 있다는
점입니다.

기본 동작은 `agent/tests/test_detection.py`에서 반복 호출·빈 결과 전환·출처 있는/없는
숫자를 검증합니다.

같은 이유로 데이터 모델에 모델의 자기보고(확신도 등)나 추정 점수가 없습니다.

## 정확도의 분모

**에이전트가 내린 결정**입니다. 사용자 요청(`chain` 루트)은 에이전트의 판단이
아니므로 세지 않습니다 — 세면 요청이 많은 런일수록 정확도가 공짜로 올라갑니다.

## 압축은 판정이 아닙니다

Codex 의 `context_compacted` 는 타임라인에 **사건**으로 남기고 판정으로 올리지
않습니다. 창이 차면 압축은 정상 동작이고, 긴 세션마다 오류를 띄우면 그 신호는 곧
무시됩니다. 대신 뒤따르는 컨텍스트 소실이 설명됩니다.

## 스킬 후보

세션을 **넘어** 반복되는 패턴은 판정이 아니라 제안입니다 (`/skills`).
한 세션 안의 반복은 이미 `repeated-call` 이고, 여러 세션에 걸친 반복은 스킬이
되어야 할 신호입니다. 이것도 세어서 나온 값이며 모델에게 묻지 않습니다.
